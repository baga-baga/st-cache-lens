# Cache Lens 0.1.5

可安装的 SillyTavern 缓存诊断与受约束优化扩展。支持前端请求观察、来源追踪、差异回放、费用分账、优化副本、回滚和可配置 AI Agent；可选本地 relay 用于观察酒馆转换后的真实上游请求并添加经过校验的 Anthropic 缓存断点。

**核验基线：SillyTavern 1.19.0，Node.js 20+。运行时无额外 npm 依赖。** 安装包包含完整源码和测试，正常安装不需要构建或 npm 安装；开发者运行全套测试需安装包内锁定的开发依赖。

0.1.3 增加一键扫描当前绑定世界书、预设和记忆来源，自动跟随切卡，以及一次授权后的跨角色受约束排序。日常使用无需逐条截图、手选每个条目或先配置 Agent。自动脱敏观察存档和中文差异说明继续保留。**从 0.1.1 / 0.1.2 升级只需更新前端并刷新；这批新功能无需重装已有服务端组件。**

0.1.4 修正诊断说明与导出：显示保护规则拒绝原因的分类计数，设置报告包含候选状态与拒绝码；已匹配不等于可重排，未知扩展不再被误写成预设顺序未知。世界书派生预算明确使用 Cache Lens 上下文上限，不能冒充酒馆扫描预算。此更新不放宽排序保护，也不代表零候选问题或实际缓存失效已经解决。

0.1.5 修正自定义标签名的兼容范围：支持原样配对的中英文括号、方括号和全角冒号，不修改标签文本、不归一化、不跨作用域重排。未支持的标签可导出解析位置和有限符号码点，不包含标签名称或属性值。此修复通过合成用例复现与验证；旧报告未记录具体标签，不能据此宣称用户实际零候选已经解除。其他结构和输入预算检查仍可能阻止应用。

## 手机先这样用

1. 在 Cache Lens 顶部点击 **“扫描当前角色全部配置（免费）”**。插件读取当前绑定的书和预设，汇总常驻/关键词/向量条目、前部动态内容、重复文本及观察缺口；不会生成剧情或调用 Agent。首次点击也会开启免费的自动跟随扫描。
2. 正常游玩，让插件取得正文请求。若仍显示待归类，确认当前接口与模型只用于正文后，点击 **“将当前连接的未归类请求标为正文”**；DeepSeek 摘要另设用途。同一模型兼做摘要时不要用这条整连接规则。
3. 填写真实的输入/上下文上限和输出预留，点“保存边界”后重新扫描。报告有合格候选后，点击 **“启用跨角色安全排序”** 一次即可。后续同一接口与模型的正文请求各自重新检查激活条目；切卡不会沿用旧卡文字，不用逐条勾选。
4. 继续正常游玩看 usage、费用与剧情质量。要停止，切回“只诊断”并点“保存边界”；要撤销本次策略，点 **“恢复上一批量设置”**。

排序只在本轮已激活、唯一定位、同消息与同作用域的相邻完整世界书片段内，把合格常驻资料放到按需资料前。它保留原书内容、触发方式和排序字段；概率 100% 的关键词条目仍是按需条目。全是关键词条目、原顺序已合适、宏/标签/作用域不明确或保护上界过大时，保持原样。**这里的“安全”指通过已实现的结构保护，不证明语义完全独立，也不保证缓存或费用改善。**

输入保护使用完整请求的 UTF-8 字节保守上界，长中文提示词可能被跳过，即使其实际 tokens 没有超限。它不是精确分词结果；不要为了启用排序把真实上下文上限调大。扫描读取的整书内容只用于本机分析，不会上传整本世界书。Agent 是另行配置预算后的可选报告复核，不是完成免费扫描与本地排序的前提。详见 [操作说明](docs/USAGE.md)。

## 使用酒馆自带“安装扩展”

打开酒馆的“扩展 → 安装扩展”，粘贴下面的仓库地址：

```text
https://github.com/baga-baga/st-cache-lens.git
```

安装完成后刷新页面，在扩展设置中打开 **Cache Lens**。仓库根目录包含 `manifest.json` 和入口文件，不需要解压、运行安装脚本或执行 npm 安装。更新可使用酒馆扩展管理器的更新按钮，以实际显示的版本为准。首次使用保持“只诊断”，点击顶部免费扫描，再配置用途与实际价格并正常游玩。

仓库只发布插件代码、文档与明确标注的合成测试素材；不要提交真实 API 密钥、聊天、世界书、请求导出或本机 relay 配置。

酒馆的“安装扩展”安装的是前端部分。可直接使用被动观察、本地诊断、回放与受约束请求副本优化；优化 Agent 的服务端密钥托管和完整出站请求观察，需要另外启用可选服务端组件。仓库链接本身不会自动获得服务端安装权限。

### 已通过扩展按钮安装，继续启用 Agent

无需再下载 ZIP。先停止酒馆，在酒馆根目录执行（默认用户、个人扩展安装）：

```bash
node data/default-user/extensions/st-cache-lens/scripts/install.mjs --st . --server
```

该命令在 Termux、Windows PowerShell、macOS 和 Linux 中相同。非默认用户将 `default-user` 替换为你的用户目录名，并追加 `--user 用户目录名`；若安装时选了“所有用户”，脚本路径改为 `public/scripts/extensions/third-party/st-cache-lens/scripts/install.mjs`。

然后在酒馆根目录 `config.yaml` 中将 `enableServerPlugins` 设为 `true`，重启酒馆。只加 `--server` 会保留前端 Git 仓库及扩展管理器更新能力。只有发布说明要求同步服务端代码时，才需停止酒馆并重新执行上述命令；已有 0.1.1 服务端时，0.1.2 存档与 0.1.3 批量功能均只更新前端。完整出站请求观察还需按 [使用说明](docs/USAGE.md) 配置本地 relay。

## OpenAI 最短配置步骤（0.1.1 起）

1. 在酒馆扩展管理器更新 Cache Lens，刷新页面。展开“优化 Agent · 连接与模型设置”。
2. 点击“检查服务端”。若提示未安装或版本旧，按上方命令安装/更新服务端，启用根配置开关并重启酒馆。
3. 点击“一键填写 OpenAI”，会填入 `https://api.openai.com/v1/chat/completions`、`gpt-6.1-terra`、输出上限和价格快照。API 密钥只在界面输入。
4. 点击“检查连接与模型（不生成）”。它只查询模型信息，不发剧情、不生成内容，也不消耗插件的生成次数预算；通过仅表示密钥被接受且模型可见，不能证明余额或实际生成成功。
5. 自行设置 Agent 调用次数与费用上限，点击“保存配置与预算”。默认都是 0；一键填写不会授权付费调用。保存不会运行 Agent。

当前 OpenAI 起步配置选 `gpt-6.1-terra`，用于有限范围的结构化修改提案。标准价格快照（2026-11-12）：每百万输入 $1、缓存读取 $0.05、输出 $5；缓存创建30分钟 $1.25、12小时 $2.50。来源：[官方模型文档](https://developers.openai.com/api/docs/models/gpt-6.1-terra)。这不是用户账号可用性或效果保证；实际生成仍需用户正常工作流验证。

0.1.1 对 OpenAI 官方域名请求标准处理档位，使用 `max_completion_tokens`；其他兼容服务默认仍用 `max_tokens`，可在高级选项按服务商文档切换。模型查询失败也可能是密钥无模型读取权限或中转不提供该查询接口，并不自动证明生成不可用。

## 使用交付 ZIP 安装

1. 解压安装包，停止酒馆。
2. 用下面的安装命令安装前端；需要 Agent 或 relay 观察界面时同时安装服务端组件。
3. 重启酒馆，在“扩展设置”打开 **Cache Lens**，保持“只诊断”。
4. 点击免费扫描，明确设置 Claude 正文、DeepSeek 摘要的用途映射，填写实际价格；正常游玩两轮。
5. 查看批量报告和相邻请求差异。有合格方案时一次启用跨角色排序；需要完整 API 证据时再接入 relay。

没有设置额外次数和费用预算时，不会调用付费 Agent。本版本不自动发起正文付费测试，也不通过无意义请求预热缓存。

## Android / Termux 安装

酒馆通常已有 Node.js。先检查 `node --version`，要求 20 或更新版本。首次访问手机下载目录可运行 `termux-setup-storage`；如果缺少 unzip，可用 `pkg install unzip`。在 Termux 中运行，路径按你的实际位置替换：

```bash
cd "$HOME"
unzip "$HOME/storage/downloads/st-cache-lens-0.1.3.zip"
cd st-cache-lens
node scripts/install.mjs --st "$HOME/SillyTavern" --frontend --server
```

若只想被动诊断、回放和本地优化，去掉 `--server`。不是默认用户时追加 `--user 你的酒馆用户目录名`。本包不会写入其他用户的扩展目录。

安装服务端组件后，在 **SillyTavern 根目录**的 `config.yaml` 中设置：

```yaml
enableServerPlugins: true
```

不要编辑 `default/config.yaml`。随后用原来的启动方式重启酒馆，刷新浏览器页面。服务端组件允许保存 Agent 密钥和访问本机 relay；前端诊断本身不要求打开这个开关。

安装脚本先暂存、检查并发修改，再替换 Cache Lens 自身目录。已有安装会备份到 `data/<user>/cache-lens-install-backups/…`，不会覆盖角色卡、聊天、原世界书、原预设或其他插件。

## Windows / macOS / Linux 安装

解压后停止酒馆，在包目录打开终端。Windows PowerShell 示例：

```powershell
node .\scripts\install.mjs --st "D:\SillyTavern" --frontend --server
```

macOS / Linux 示例：

```bash
node scripts/install.mjs --st "$HOME/SillyTavern" --frontend --server
```

同样在酒馆根配置中启用 `enableServerPlugins: true` 并重启。Node 版本要求与手机一致；安装脚本支持空格路径。

## 本版本实际能做什么

| 功能 | 实现范围 |
| --- | --- |
| 请求观察 | 酒馆前端事件与最终前端 fetch；本地 relay 另外观察服务端转换后的出站请求及 usage。两层不会混为一份。 |
| 来源与差异 | 保留空白及不可见字符，比较角色、块顺序、最早差异和稳定前缀；来源精确匹配与启发式判断有区别。 |
| 自动脱敏存档 | 当前酒馆账号在本浏览器保留最近最多 1000 条 / 2MiB 元数据；刷新恢复统计与已保存的差异摘要，不保存原始提示词。 |
| 世界书 | 分开显示整书、预算、激活和发送量；读取整书只是本机诊断，不等于把整书注入模型。 |
| 批量诊断 | 自动汇总当前全局、角色主/附加、聊天、用户人格绑定书、当前预设顺序及公开扩展来源；自动跟随切卡与正常请求，无需逐条操作。 |
| 跨角色排序 | 一次授权当前正文接口与模型，后续按每个请求自身激活快照重新生成同作用域排序副本；常驻/召回两类内部相对顺序保留，不改原书字段。 |
| 高级结构优化 | 保留手选独立片段、建立副本、预览/应用的细粒度方式；字节不再匹配就跳过，不注入旧状态。 |
| Agent | OpenAI Chat Completions 兼容或 Anthropic Messages 端点；服务端保管密钥。批量入口仅复核有界诊断元数据；高级副本可提受限结构方案，仍须本地校验与预算检查。 |
| 缓存断点 | 在经过确认的 Anthropic Messages 接口，为两次实际请求中相同的 system 块前缀添加真实 API 断点；保留现有断点和原文本。 |
| 摘要适配 | 检测摘要重写/时间措辞变化/位置移动；提供追加式记忆台账与只读适配接口。未知第三方摘要插件不自动改写。 |
| 费用与回滚 | 正文、摘要、Agent 分账；单价、币种、来源和日期可配置；方案版本、并发检测、试算、历史及回滚。 |

这个版本没有接管未知“类脑缓存命中管理”插件的内部状态，也没有实现对任意第三方摘要的自动语义压缩。预设与记忆参与批量诊断，但新的跨角色策略只排序合格的已激活世界书片段。它不自动修改原世界书触发策略、消息角色或秘密揭露条件。可执行范围不足时，诊断保留证据，优化跳过；无需为得到非零修改数强行调整设置。

## 安装后怎样验证

```bash
npm ci --ignore-scripts
npm test
npm run check
npm run demo
```

测试依赖包含 jsdom 26.1；仅用于开发验证，不是手机运行插件所必需。测试包含离线请求回放、usage/费用计算、越权拒绝、并发与回滚，以及真实本机 HTTP mock 上游。`npm run demo` 使用明确标注为 synthetic 的离线样例，不连接付费模型。最终测试数量与检查结果见交付测试报告。

已在开发环境启动官方酒馆 1.19.0，加载服务端插件并完成前端打包。官方酒馆 HTTP 集成验证覆盖前端模块访问、身份验证/CSRF、官方请求转换、relay 与 mock 上游的 JSON/SSE 请求，以及原生非流式响应缺少 usage 时由 relay 恢复观察。界面控件另作 DOM 级验证；开发环境的浏览器沙箱限制阻止了实际手机视口的视觉验收，不把控件测试表述为手机视觉测试。

**尚未在你的 Termux 设备、真实 Claude/DeepSeek 账户或中转站付费请求上验证。** 离线测试通过不代表 Claude 缓存读取已经提高，更不能保证总费用一定降低。总费用必须在正常连续游玩中实测，同时评估剧情质量。

观察内容会包含剧情文本，保存范围分开处理：

| 内容 | 保存与恢复范围 |
| --- | --- |
| 原始提示词 | 当前页面最多 30 条、约 24MiB 内存；刷新后原文不保留。每个 relay 另有默认最多 20 条、32MB 的进程内存记录。 |
| 本页用量元数据 | 当前页面最多累计 10000 条，达到上限会提示累计不完整。 |
| 自动脱敏存档 | 当前账号、本浏览器 localStorage 最多 1000 条 / 2MiB，保留用量、模型、用途、时间、状态、最早差异位置/偏移及前次比较状态，不保存提示词、来源正文、请求 endpoint 或凭据。 |

刷新后恢复全部有界存档供统计，选择列表恢复最近 30 条。存档只能回顾已有结论，不能与新请求重新逐字比较，也不能用于提取优化片段。清除浏览器数据、更换浏览器或超过保留上限后，不能承诺恢复被丢弃的记录；此前未保存的原始请求无法补回。

优化副本、回滚记录和记忆台账有独立持久化，并镜像到酒馆扩展设置；跨标签提交使用 Web Locks 与精确版本比较；脱敏观察存档写入也要求 Web Locks，缺少时明确提示且不写入。浏览器必须使用 localhost 或 HTTPS 安全上下文；缺少锁能力时不能提交优化修改。“清空观察与本机存档”只清空观察记录，不重置优化副本、回滚记录或服务端 Agent 预算。默认脱敏导出不包含提示词正文；记忆导出与主动获取的完整请求仍可能包含秘密剧情，分享前应检查。密钥不应放进角色卡、世界书、截图或聊天。
