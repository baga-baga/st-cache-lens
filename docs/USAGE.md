# Cache Lens 使用说明

本说明对应 0.1.2。已有 0.1.1 时，在酒馆扩展管理器更新 Cache Lens 并刷新页面即可；本次改动在前端，已安装的 0.1.1 服务端组件无需重装。更新不会恢复此前已经丢失的原始提示词。

## 1. 先只观察正常游玩

安装后打开扩展设置中的 **Cache Lens**。默认模式为“只诊断”。填写：

| 字段 | 含义 |
| --- | --- |
| 单轮输入上限 | 优化副本与断点策略允许处理的输入边界。不是整本世界书的大小限制。 |
| 上下文上限 / 输出预留 | 给当前模型上下文留下输出空间。按实际上游限制填写，不按模型显示名猜。 |
| 额外调用次数上限 / 费用上限 | 用于优化 Agent 的额外付费授权；默认均为 0。不会启动正文压力测试。 |
| 运行模式 | 只诊断；预览后应用；受约束自动优化。 |

单轮保护约束本插件的改动，不会替你拦截原来正常发送的剧情请求。缺少精确 tokenizer 时，优化采用保守的 UTF-8 字节上界并预留协议开销；这会跳过部分实际 token 数可能仍合法的大请求。跳过不是测得超限，更不能为“让优化生效”随意提高模型真实上下文限制。

需要修改配置时，用支持 Web Locks 的浏览器通过 `http://localhost:酒馆端口` 或 HTTPS 访问酒馆。普通局域网 HTTP 地址可能不是安全上下文，无法使用锁时插件降级为只读诊断。优化状态、回滚记录和记忆以当前酒馆账号隔离，保存在该浏览器的 localStorage，并镜像到酒馆扩展设置；同源标签页通过 Web Locks 与精确状态比较避免互相覆盖。清理浏览器站点数据会影响本机状态；换浏览器/设备后应重新检查当前副本和镜像，不把跨标签锁理解为跨设备的全局锁。

“用途映射与价格”中，按**实际记录的接口来源和完整模型 ID**添加规则，例如 `claude` + 实际 Opus ID → 正文，`deepseek` 或 `custom` + 实际 DeepSeek ID → 摘要。只有显式规则或已验证适配器才确定用途；没有证据的请求保留“待归类”。也可在所选请求的“更正此请求用途”中手动标记。

同一模型可用于多种任务；如果你的调用路径无法区分它们，不应创建覆盖全部用途的模型规则，应采用逐请求标记或专门适配器。

价格 JSON 的键是 `provider:model` 或完整模型 ID。下面全部是**演示价格，不是当前报价**：

```json
{
  "YOUR_ACTUAL_MODEL_ID": {
    "input": 1,
    "cacheWrite5m": 1.25,
    "cacheWrite1h": 2,
    "cacheRead": 0.1,
    "output": 5,
    "currency": "USD",
    "source": "填写实际服务商价目表 URL",
    "updatedAt": "2026-11-12"
  }
}
```

单位均为每百万 tokens。OpenAI 新版 Responses 写入还可填写 `cacheWrite30m`、`cacheWrite12h`；DeepSeek 缓存未命中按普通输入计费。缺少需要的价格或 usage 时显示未知，不显示为免费。估算费用与平台扣款是不同证据；中转加价、折扣及阶梯价格需要核对账单。

正常游玩两轮后，选择同一模型/用途/接口/观察层的相邻请求。查看“最早差异、稳定前缀与来源”和“当前请求 / usage / 来源”。空白及不可见字符不会自动归一化。旧摘要换字、动态世界书增减、变量快照和骰池可形成不同来源；仅仅内容相关不等于重复注入。

差异面板先显示中文说明，原始诊断 JSON 另行展开。它会写明当前请求与比较对象的时间、状态：默认比较时间上相邻的同组记录，其中可能包含失败请求。`http-error` 表示请求失败，不代表成功生成或已建立缓存；失败请求仍可能产生费用，须看 usage 或平台账单。状态未知不能当作成功。

`messages[6].content` 指第 7 条 **API 消息**，不是第 7 轮聊天；`messages[21].content` 同理指第 22 条 API 消息。`structure` 表示角色、块边界、内容类型或元数据等结构差异，`offset=0` 只是比较在该段起点停止，不能直接断定第一个字变了或前面历史被裁剪。稳定长度采用 UTF-16 代码单元，不能当作 token 数或实际缓存读取量。摘要重写/相对时间变化标记也不能单独证明同一事件日期被改写或零命中的唯一原因。

## 2. 解释 150 万 tokens

展开“世界书：整书、预算、激活、发送”。可读取选中的世界书做本机检查。四个数字分别表示：

| 数值 | 可以证明什么 |
| --- | --- |
| 整书总量 | 存储的全部条目内容有多大，不证明本轮全部激活。 |
| 预算上限 | 配置允许世界书占用多少上下文，不是已发送量。 |
| 本轮激活量 | 当前观察到的激活条目量；需注明 token 计数方法。 |
| 最终发送量 | 有最终请求或 usage 证据时的输入量；无法归因的世界书份额显示未知。 |

不要把孤立的“1500000”直接当成实际发送量。插件不会通过全书常驻、无限预算或重复注入解决此问题。

## 3. 建立优化副本与应用

1. 在一次正文请求后，选择当前页面仍保留完整上下文的前端层记录，点击“从当前请求提取候选片段”。标有“存档”的脱敏记录没有原文，不能提取优化片段。
2. 只为确实互相独立、先后顺序不承担指令作用域或剧情顺序的片段勾选“独立可重排”；对稳定基础资料另勾选“稳定”。至少选择两个。
3. 点击“建立优化副本”。副本绑定当前聊天、模型、接口来源和正文用途；原世界书和预设文件不被覆盖。
4. 点击“本地生成排序方案”，或配置 Agent 后点击“调用 Agent 提案”。本地方案把已选稳定片段排在同组动态片段前。
5. 查看“校验与离线试算”的前后顺序、理由和估算，再在预览模式点击“应用到优化副本”。自动模式可对通过全部检查的提案直接应用。

运行时只改写本次请求的副本。适用片段必须处于同一个文本位置、同一消息角色与作用域，完整字节唯一匹配，相邻间隔仅为空白。出现标签不配对、宏展开导致不匹配、条目增减、片段歧义或预算不满足时，整组跳过。不会跨消息移动角色、用旧变量覆盖新变量、把全书设为常驻，或删除角色事实。

这也是为什么有时界面会说“没有可安全重排片段”：不能从未知插件的内部组织方式推断可任意移动。此时继续保留诊断，补充明确适配器后再扩展操作范围。

“恢复本轮修改”按时间恢复最近的副本或 relay 策略修改；“恢复优化前”依次恢复所有观察器的本插件策略修改和结构副本，并停用自动优化。请求进行中不能修改，版本改变后必须重新预览。此处恢复的是本插件管理的配置，不会撤销用户已收到的剧情文本，也不能删除服务商已经写入的缓存。relay 断点也有独立的“恢复上一断点策略”按钮。每次远程修改先持久化意图，保存失败会尝试带版本检查的补偿恢复；断网或并发修改导致状态不确定时，保留待恢复事务，使用“恢复未完成的策略事务”。多观察器回滚不是分布式原子事务，后续冲突会明确停止，已完成的恢复仍在审计记录中。

## 4. 配置优化 Agent

0.1.1 在“优化 Agent · 连接与模型设置”中按四步完成：

1. **检查服务端**：需要安装/更新可选服务端组件，启用酒馆根配置的 `enableServerPlugins: true` 并重启。前端更新不会自动更新服务端。
2. **一键填写 OpenAI**：填入官方完整 Chat Completions 地址、`gpt-6.1-terra`、最大输出 4096、推理强度 low 和标准价快照；币种 USD，输入 $1/百万、输出 $5/百万、缓存读取 $0.05/百万、缓存创建30分钟 $1.25/百万和12小时 $2.50/百万，核对日期 2026-11-12。只填表单，未保存，不修改零预算。然后自行填写 OpenAI API 密钥。
3. **检查连接与模型（不生成）**：通过酒馆服务端 GET 查询同一上游 `/models/{model}`。不发送剧情、不生成内容、不修改预算或保存配置；只证明请求通畅、凭据被接受和模型信息可见。模型读取权限、代理查询支持与生成权限不同；未检查余额或实际生成。此检查支持 OpenAI 兼容接口，Anthropic 仍可保存配置并在既有预算内调用。
4. **保存配置与预算**：在同一栏设置正数的次数、费用上限；由用户决定额度。密钥只由同源服务端保存，成功保存后输入框清空。保存不会调用模型。

手动填写完整 endpoint 时，OpenAI 兼容接口需到 `/v1/chat/completions`，Anthropic 需到 `/v1/messages`。官方 API 与中转密钥不能混用。切换到官方预设时会清空其他 endpoint 对应的待填密钥；服务端只在地址完全相同时复用已有密钥。默认关闭“允许本机回环 API”。

价格与高级选项中可核对价格、币种、来源、日期、缓存价格和输出限制参数。官方 `api.openai.com` 显式请求 `service_tier: default` 标准档位，自动用 `max_completion_tokens`，包含可见输出与推理 token；其他 OpenAI 兼容接口自动用 `max_tokens`，可按其实际文档显式选择。Anthropic 始终用 `max_tokens`。价格是快照而非自动更新数据，更换模型或服务商后必须更新价格。

保存后，在已经建立的优化副本上点击“调用 Agent 提案”。默认只发送差异类别、计数、片段 ID、长度及边界设置，不发送整本世界书或片段全文。Agent 只能在已有授权结构范围内提出顺序修改，无法自行判断被隐藏的剧情语义是否可删。

Agent 返回 JSON 后仍须本地校验。它没有任意文件系统写入、Shell、网页或工具执行权限；角色卡、世界书和摘要中的命令只是分析数据。每次生成前按输入上界和最大输出预留费用。失败、usage 缺失或无法计价时保留保守预留，不无限退款重试。

预算不会因刷新页面重置。服务端显式重置接口要求 `{ "confirm": "RESET" }`，普通配置保存不重置累计费用。没有用户配置的正数预算时不调用生成模型。

## 5. 观察服务端最终请求：本地 relay

前端能观察的是酒馆前端发给酒馆服务器的内容。若要检查转换后实际送上游的 `system/messages/cache_control`，使用本包 relay。它只监听 `127.0.0.1`，固定转发到一个配置的上游；用户正常发送一次，relay 转发一次，不生成额外测试。

### Termux / macOS / Linux

在解压包目录操作：

```bash
mkdir -p "$HOME/cache-lens-private"
cp server/relay.example.json "$HOME/cache-lens-private/relay.json"
chmod 700 "$HOME/cache-lens-private"
chmod 600 "$HOME/cache-lens-private/relay.json"
```

编辑 `relay.json`：`interfaceType` 按实际协议选择 `anthropic` 或 `openai`，`upstreamBaseUrl` 改成**你当前真正使用的供应商/中转基地址**。示例默认官方 Anthropic，不要误把自己的中转密钥发到错误服务。基地址可带 `/v1`，不要填到 `/messages` 或 `/chat/completions`。保留 `host: "127.0.0.1"`。

`modelPurpose` 是你明确设置的完整模型 ID → 用途规则，例如正文 `main`、摘要 `summary`；不是程序猜测模型用途。若正文和摘要使用两个不同上游，分别启动两个 relay 配置：各自有固定上游、自己的密钥、本地令牌和不同端口。例如正文用 `8937`，摘要用 `8938`。界面可登记最多 **4 个观察器**，同时汇集它们已有的请求；一个 relay 仍只转发到一个固定上游。

relay 另有可选的**发送前硬限制**。需要它直接阻止超限请求时，在 `relay.json` 增加下面字段，并按真实模型限制调整：

```json
{
  "maxInputTokens": 160000,
  "contextTokens": 200000,
  "outputReserveTokens": 8192
}
```

这些字段合并进原配置，不是替换整份配置。启用后会用完整请求 UTF-8 字节数加协议开销作保守上界，并按请求的输出上限和配置预留取较大值。超界返回 HTTP 413，无法可靠估算的多模态等内容返回 422，均在发送上游之前拒绝。这不是精确 tokenizer 计数，可能拒绝实际 tokens 尚未超限的长中文请求。示例配置默认没有 token 硬限制，仅有 8MB 的请求字节上限；面板的优化边界不会自动替你启用 relay 硬限制。

从终端安全读入上游密钥，避免把明文写进命令历史：

```bash
read -rsp '上游 API 密钥（仅本机输入）: ' CACHE_LENS_UPSTREAM_KEY
export CACHE_LENS_UPSTREAM_KEY
printf '\n'
export CACHE_LENS_RELAY_TOKEN="$(node -e "console.log(require('node:crypto').randomBytes(24).toString('hex'))")"
printf '本地 relay 令牌：%s\n' "$CACHE_LENS_RELAY_TOKEN"
node server/relay.mjs "$HOME/cache-lens-private/relay.json"
```

本地 relay 令牌需至少 24 字节。把上一步生成的**本地令牌**保留在自己的密码管理工具中，后续填给酒馆和观察器；它不是上游 API 密钥。不要截图公开。relay 进程所在终端需要保持运行；Android 后台可能被系统终止，应按你现有 Termux 后台运行习惯管理，不能假设锁屏后永远在线。

### Windows PowerShell

在包目录复制配置到一个私有目录并编辑上游地址：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\cache-lens-private"
Copy-Item .\server\relay.example.json "$env:USERPROFILE\cache-lens-private\relay.json"
$cacheLensSecret = Read-Host "上游 API 密钥（仅本机输入）" -AsSecureString
$env:CACHE_LENS_UPSTREAM_KEY = [System.Net.NetworkCredential]::new("", $cacheLensSecret).Password
Remove-Variable cacheLensSecret
$env:CACHE_LENS_RELAY_TOKEN = node -e "console.log(require('node:crypto').randomBytes(24).toString('hex'))"
Write-Host "本地 relay 令牌：$env:CACHE_LENS_RELAY_TOKEN"
node .\server\relay.mjs "$env:USERPROFILE\cache-lens-private\relay.json"
```

### 酒馆端连接

| 酒馆连接 | 地址 | 密钥/密码位置 |
| --- | --- | --- |
| Anthropic 来源的 Reverse Proxy | `http://127.0.0.1:8937` | Proxy Password 填本地 relay 令牌 |
| OpenAI 兼容自定义基地址 | `http://127.0.0.1:8937/v1` | 该连接的 API key 填本地 relay 令牌 |

上游真实密钥仍仅在 relay 进程环境中。不要在 relay 地址里放真实密钥。`127.0.0.1` 指**酒馆服务器所在设备**；若手机浏览器连接另一台电脑的酒馆，relay 应运行在那台电脑，而不是手机。

本 relay 只支持推理端点，不提供 `/models` 列表；如果酒馆自定义连接不能自动拉取模型列表，手动填写已经核实的模型 ID。不要为了连通关闭 TLS 校验或把 relay 改成公共监听。

在 Cache Lens 的“服务端实际请求与缓存断点”填观察器 ID、relay 地址和对应的本地令牌，点击“连接本地观察器”。默认 ID 是 `main`；为摘要端另填 `summary` 与它的端口/令牌再保存。每个 ID 保留独立配置，最多 4 个。正常游玩后选择“服务端 relay”观察层，刷新会汇集所有已配置观察器；某个不可用时单独报告该观察器错误，不把其他观察器的记录一起丢弃。界面在空闲时约每 15 秒轮询已有记录，轮询不调用模型。同一请求在前端和 relay 两层的记录不会直接相加计费。

relay 记录的是酒馆转换后、relay 真正尝试发送/已取得上游响应的内容，并注明传输状态。中转内部再次转换、号池路由和缓存归属仍不可见。没有这层证据时，前端不会冒充已看到服务端请求。

## 6. 在稳定前缀处添加真实缓存断点

目前自动提取仅适用于已核实的 Anthropic Messages 协议，不向不明 OpenAI 兼容接口注入 Anthropic 字段。

1. 在 relay 层获得同一模型/用途的两次实际请求。
2. 先确认观察器 ID 对应本次正文 relay，再点击“读取当前断点策略”，记录当前版本。不同观察器的策略独立。
3. 点击“从两次实际请求提取稳定 system 前缀”，查看提取到的完整 system 块及策略。
4. 按上游文档核对模型、TTL 和缓存支持，确认后勾选接口核实项；切换到允许应用的模式，再点击应用。
5. 通过后续正常游玩的真实 usage 检查 `cache_read_input_tokens` 等字段，并同时比较费用、写入量和延迟。

此策略只加结构化 `cache_control`，不改写正文。已有自动缓存、目标已含断点、断点数量不足、TTL 冲突、前置 tools 未证明稳定、非文本无法估算、输入上界超限或前缀改变时跳过。不会为了达到最小 token 阈值添加无关内容。标记放置成功不等于本轮服务商实际缓存读取。

点击“恢复上一断点策略”回滚本插件应用的策略，它只恢复当前观察器最近的修改。relay 策略只在进程内存中保留；重启后回到配置文件的初始策略，旧版本记录不应再被强制覆盖。没有配置 `cachePolicy` 的示例默认只观察、不变更。

## 7. 摘要、记忆与实际效果

现有第三方摘要保持只读。“稳定记忆适配”可以追加带唯一 ID、准确 ISO 剧情日期、原相对时间措辞和已确认事件的记录。旧事件不自动改写；台账不会自动重复注入请求。明确的外部适配器可以读取 `CacheLens.getMemory()`，真正接管某个摘要插件前必须验证它的公开接口和版本。

先点击“将当前观察设为基线”，然后应用一个方案，继续正常游玩，再点击“比较后续正常游玩”。填写剧情质量：事实、连续性、秘密条件是否正常。缺少可比的模型/用途、usage 或价格时，不能宣布费用下降。评估窗口应同时包含摘要和 Agent 开销；短窗口的一次缓存重建可能需要后续多轮才回本。

若出现剧情退化，标记失败并比较评估，插件依次恢复关联的 relay 策略和优化副本并回到诊断模式；并发冲突时保留恢复记录，不覆盖他人修改。无改善或出现其他停止条件时，按评估结果停用自动优化；不继续购买无意义请求。不同观察层不直接相加，以免一次剧情请求被重复收费统计。

## 8. 导入、导出与问题排查

“导入请求 / usage / 账单”接受 JSON 对象、数组或 `{ "records": [...] }`。每条建议含 `body`（或 `request`）、`usage`、`provider`、`interfaceType`、`model`、`purpose`、`startedAt`，可附 `platformBill`。导入证据显示“用户导入”，不会假定已验证其来源。

旧版“导出脱敏诊断”的 JSON 也可导回。即使其中 Claude 记录没有 `usage` 或提示词正文，只要有已保存的诊断信息，0.1.2 仍会保留并展示；导入后选择“导入证据”层查看。它保留的是旧差异结论，不能补出缺失 usage、推算真实缓存读取，或重建原始提示词。

默认脱敏导出保留计数、差异类型和费用信息，移除提示词正文。若需要复现精确空白变化，请另行制作一致替换的脱敏原始请求；不要把已经删除正文的统计导出当成可完整回放的请求。记忆导出含事件正文，分享前自行检查。

| 现象 | 优先检查 |

## 会话统计保存边界

完整提示词仍只保留当前页面最近 30 条、合计约 24MiB 内存；较早请求的最小用量元数据在本页继续累计，最多 10000 条。达到本页上限后提示累计不完整，应导出记录再开始新观察会话。

0.1.2 自动把脱敏元数据保存到**当前酒馆账号、本浏览器**的 localStorage，按最近时间保留最多 1000 条，同时限制为 2MiB。存档包含 numeric usage、模型、用途、时间、请求状态、最早差异路径/偏移、稳定长度、诊断标记及前次比较对象时间/状态。它不保存原始提示词、来源正文或来源映射、请求 endpoint、鉴权头或密钥。写入和清空需要 Web Locks 保护多标签并发；缺少该能力时仍可读取旧存档和临时观察，但不写入，请使用 localhost 或 HTTPS。

刷新后，费用表恢复这份有界存档中的全部记录，选择请求列表恢复最近 30 条并标注“存档”。已保存的差异结论仍可查看；没有原文就不能重新逐字比较，不能用它与新原文推断新的最早差异，也不能据此应用结构优化。若要重新分析完整内容，需当前页面内正常取得两次完整请求，或导入确实包含脱敏原文的请求。

“清空观察与本机存档”清空本页请求/统计及当前账号在此浏览器中的脱敏存档；**不会重置优化副本、回滚记录、记忆台账或服务端 Agent 预算**，也不会清空 relay 进程中的记录。随后刷新服务端观察时，仍可能读回 relay / Agent 中尚存的记录。

Agent 计费记录和预算另在服务端持续保存。优化副本、回滚记录与记忆台账也有独立持久化。清理浏览器站点数据、更换浏览器/设备、存储权限或配额错误、超过保留上限，都可能使本机存档不再可用；重要诊断仍应导出保留。升级前未采集、未导出或已经丢失的原始请求，插件不能事后恢复。
