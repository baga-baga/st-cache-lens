# 验收与继续接入

本文件是验收清单，最终执行结果以交付包中的测试输出为准。测试使用脱敏固定样本、内存适配器与本机 mock HTTP 上游；这些结果不能表述为“Claude 的真实缓存命中率已提高”。

## 本地验证命令

在包目录运行：

```text
node --version
npm ci --ignore-scripts
npm test
npm run check
npm run demo
node scripts/install.mjs --help
```

Node.js 要求 20 或更新版本。核心、安装器及插件运行不需要额外 npm 依赖；完整开发测试需用锁文件安装 jsdom 26.1 等开发依赖。demo 样例明确标注 synthetic，仅供离线复现。界面测试不能替代真实供应商测试；当前浏览器沙箱阻止了实际视觉验收，DOM 控件测试不算手机视觉测试。

开发环境另外启动了官方酒馆 1.19.0，完成服务端插件加载及前端打包，并通过实际 HTTP 验证前端模块、鉴权/CSRF、官方 Claude 转换、relay 与 mock 上游的 JSON/SSE 及 usage 捕获。供应商端仍是模拟上游，不是真实付费缓存验证。

## 核心验收项目

| 场景 | 应满足的结果 |
| --- | --- |
| 聊天历史前新增/移除世界书条目 | 标出最早内容变化、来源和缩短的稳定前缀，不归因为请求 ID。 |
| 旧摘要重写、相对日期改变、固定深度移动 | 三种现象分别提供证据；仅文字变动不自动改写事实或冻结真实日期。 |
| 只向末尾追加对话 | 先前上下文保持稳定；仍不凭本地稳定断言实际读取。 |
| 稳定前缀已有有效断点、后部变化 | 报告前部候选可复用边界，而不是宣称整个缓存失效。 |
| 150 万 tokens 异常与上下文预算 | 整书/预算/激活/发送分开；超过上限或异常膨胀的自动方案被拒绝。 |
| 重复注入 | 仅精确相同内容可作重复证据；相关摘要与原剧情不能只因语义相似就删。 |
| Agent 越权、标签损坏、改写事实 | 本地确定性校验拒绝；无任意文件写入或任意工具执行。 |
| 并发修改、请求进行中、应用失败 | 停止提交或恢复先前状态，不覆盖他人刚改的配置。 |
| 本轮回滚和恢复初始配置 | 关联设置一起恢复，保留版本与原因记录。 |
| usage 与费用 | Anthropic、OpenAI、DeepSeek 的互斥计数正确；摘要与正文不会混算；字段缺失不会被当成零费用。 |
| 安装器 | 路径含空格可用；越界、符号链接与未知目标拒绝；已有安装备份；并发修改取消安装。 |
| Agent 预算 | 未配置限额不能调用；调用前预留费用与次数；错误/未知 usage 不能无限释放预算。 |
| 本地 relay | 固定上游、回环监听、令牌保护、拒绝重定向；不记录鉴权头；可观察非流式和 SSE usage。 |
| 多观察器 | main/summary 等最多 4 个观察器独立端口、令牌、上游；汇集记录并分别报告错误；前端和 relay 层不重复求和。 |
| 持久化并发 | 当前账号隔离的 localStorage、Web Locks、精确 CAS 与酒馆设置镜像；冲突不覆盖，缺锁保持只读。 |
| 一键当前配置扫描 | 读取全局、角色主/附加、聊天及人格绑定书与当前预设；不把所有可用书当成绑定书；缺书、采集超界、扫描中切卡均不得据此授权。 |
| 关键词概率与排序诊断 | 100% 关键词概率仍属按需触发；相同 order 不证明随机排序；整书估算超过输入上限不等于本轮发送超限。 |
| 跨角色批次授权 | 一次授权当前正文接口与模型；后续角色只用各自本轮激活内容，摘要/其他连接跳过，不复用前一卡片文字。 |
| 批次排序保护 | 只调相邻、唯一定位、同角色与同注入/标签作用域的完整片段；保留两类内部顺序、内容和空白；宏、变量/时间/骰池、依赖关系、未知来源保持原样。 |
| 批次零修改与超界 | 全关键词、已常驻在前或无合格范围时不制造重排；完整请求字节上界超限时跳过，不把较小分词估算冒充精确结果绕过。 |
| 批量报告与 Agent | 移动端报告按问题归类，标明原文覆盖；导出无正文；外部 Agent 仅接收有界元数据摘要，批量入口拒绝修改操作，付费仍受预算限制。 |
| 批次恢复与暂停 | 只诊断暂停排序；恢复上一批量设置同时恢复策略、关联模式与基线，检查并发；取消自动跟随仅停扫描，不等于停排序。 |

## 不依赖用户凭据即可完成

- 核验官方版本、事件载荷、服务端转换和缓存配置位置。
- 开发前端扩展、可选服务端插件、本地 relay 与跨平台安装器。
- 离线回放、模拟上游、校验、费用计算、预算和回滚测试。
- 用显式来源映射测试世界书/摘要/变量/骰池的分离，不假定第三方内部接口。

## 用户环境仍须验证

- Android/Termux 的安装、后台进程生存和实际连续游玩。
- 用户安装的酒馆准确版本及第三方插件的事件顺序/直接发请求路径。
- 中转接收断点后的转发、模型路由、返回 usage 与真实扣款是否一致。
- 经过一段连续会话后，正文 + 摘要 + Agent 的总费用是否降低。
- 剧情事实、秘密揭露条件、当前状态和变量规则是否保持正确。
- 跨角色批量授权是否覆盖用户希望优化的正文连接；各卡是否有能通过严格保护的实际片段，以及长中文请求是否经常因保守上界而跳过。

剧情质量需要用户对自然游玩结果作判断。只看费用或 token 数不能自动证明质量未下降；差评/退化应触发暂停候选方案和回滚。

## 最少接入材料

1. 酒馆版本号或提交号，以及当前调用接口类别（Anthropic / OpenAI 兼容 / 其他）。
2. 酒馆助手、自动摘要、类脑缓存插件的准确仓库链接与版本，或不含密钥的设置导出。
3. 两次相邻的脱敏实际请求与各自 usage，最好包含 relay 捕获的服务端层数据；保留角色、块顺序、空白、缓存参数和时间。
4. 各用途的价格、币种、单轮输入上限、优化 Agent 的调用次数及费用上限。

不需要重发整本世界书，不要通过聊天发送明文 API 密钥。密钥只输入本机受保护配置界面或环境变量。脱敏时应保持两个样本的一致替换规则；删除真实前缀或自动格式化文本会使差异诊断失真。

0.1.3 的“扫描当前角色全部配置（免费）”可代替逐条设置截图。需要共享时优先导出“设置报告（无正文）”，检查书名/条目名后再分享；报告只能说明配置与已观察差异，不能补全丢失的原请求或证明真实费用已经下降。
